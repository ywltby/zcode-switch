# Z·SWITCH v1.7.0-beta.13

> 本版将 [wjsqqj fork](https://github.com/wjsqqj/zcode-switch) 的领取链路实现完整移植进主线（冲突以其代码为准），并保留主线独有的代理出口与设备标识重置能力。

## 领取链路（移植）

- **marketing/touch 深度递归解析**：不再只扫 `banner`/`popup` 两个槽位，递归遍历活动下发 JSON 的所有层级，同时识别 `claim_zcode_plan` 与 `claim_plan` 两类按钮——修复"新版活动查不到 / 查资格返回空"
- **已领取状态判定**：新增 `billing/current` 查询与本地领取历史，界面区分「无活动 / 已领取生效中 / 已领过」，不再把已领账号误报为无资格
- **领取错误分级**：challenge / terminal / captcha_rejected 分开处理；3007 拒码不再自动换码重试（上游风险信号，连打加剧风控）
- **活动中心**：活动探测调度（可开关）、托盘红点与系统通知、活动详情弹框、到点自动领取（独立开关）
- **风控门禁 risk.rs**：上游失败进入账号级冷却，冷却期内额度查询直接拦截，避免加剧风控
- **claim 日志落盘**：`marketing-fail`、`captcha-config-fail`、`captcha-rejected-3007` 写入 flowlog，领取失败可在 `logs/oauth.log` 追溯服务端响应
- 配套 mock 上游测试矩阵与 CHANGELOG

## 主线保留能力（重新挂接）

- **代理覆盖业务请求**：设置的代理作用于领取预览/提交、营销活动查询、激活上报、验证码配置与额度查询全部请求；换代理节点出口即换资格环境；地址无效自动退回直连
- **重置设备标识**：账号行「重置设备标识」按钮 + CLI `reset-device --id <账号>`，换新设备 id 等效于手动删除 ZCode 的 `telemetry-state.json`

- `cargo test` 25 项（含对方 mock 上游矩阵 16 项）、前端 100 项、i18n 298 键、`vite build` 全部通过
- 本机 NSIS 打包：`zcode-switch_1.7.0-beta.13_x64-setup.exe`、`zcode-switch_1.7.0-beta.13_portable.exe`、`checksums-Windows-v1.7.0-beta.13.txt`
