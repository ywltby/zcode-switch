# Z·SWITCH v1.7.0-beta.14

> beta.13 整体移植 [wjsqqj fork](https://github.com/wjsqqj/zcode-switch) 的领取实现时，覆盖了主线已有的账号隔离与领取保护。本版保留其领取协议（preview、marketing/touch、billing/current、claim）与活动功能，把这些保护重新接回。

## 当前登录

- 资格查询、刷新、领取快照与结果回填使用当前登录自身的凭证和设备 ID，不读写 `accounts/live.json`，不创建或改写客户端设备文件
- 请求期间切换登录，旧结果因身份或版本变化被拒收；迟到的领取结果不会标记到新登录上
- 已领取标记、活动目录与进行中的查询按真实身份隔离；把已保存账号更新为另一个登录时从干净状态开始

## 代理与版本

- 额度、领取、活动查询与激活上报共用一份代理设置（`net.rs`），GUI 与 CLI 一致
- 领取 / 活动请求的版本号按数值比较已探测版本、内置版本与 changelog 缓存，取最高的有效值，并同时带在 URL 参数和请求头里
- OAuth 登录使用独立的固定版本，修复活动版本不会改变登录协议

## 自动领取

- 未开始、已过期、本地已标记领取的活动不会被自动提交；手动查到资格仍立即入队，到点后才提交
- 领取成功后持久标记，服务端短期仍返回旧资格、冷却后再扫描或程序重新加载都不会重复领取
- 旧账号代次、删除重加、资格撤销和查询失败不会触发旧任务；同一时间只有一个领取会话

## 结果分类与风控

- 缺少或无法识别业务码、传输或响应读取异常记为「结果未知」，不自动重试；明确的业务拒绝记为失败
- 保留业务 `code`、终态、验证码挑战和下次可领时间：1005 沿用上游时间，3007 不自动换码重试，验证码挑战不误判为登录失效
- 领取准备中预览返回 3012 / unusual activity 时记录冷却并中止，不弹验证码、不发送领取请求

## 领取记录保护

- 损坏、无法读取或版本不支持的领取记录保留原文件，不被覆盖或清空，自动、到点与批量领取都会被拦下
- 提交标记写入失败时不发送请求；重启时「提交中」转为「结果未知」
- 结果未知需人工确认；失败重试不会清除旧的未知记录，只有确定成功才清除

## 发布配置

- 恢复「带 `-` 的标签一律为预发布」，移除随移植带入的对方发布说明与发布身份设置
- CI 新增 mock 上游测试、原生切换安全回归与浏览器 UI 回归，全部使用合成账号和本地 mock

## 本机验收

- `cargo test --lib` 113 项（1 项需外网，默认跳过）、mock 上游 29 项、原生切换安全 8 项
- 前端 141 项、浏览器 UI 回归 12 套、i18n 327 键、`vite build` 全部通过
- 以上均为合成数据与本地 mock；真实上游领取、原生窗口与 macOS / Linux 未在本机验证

Windows 安装包：`zcode-switch_1.7.0-beta.14_x64-setup.exe`、`zcode-switch_1.7.0-beta.14_portable.exe` 和 `checksums-Windows-v1.7.0-beta.14.txt`。
